# ТЗ: Проектирование хранилища артефактов СА в MongoDB

## 1. Цель
Реализовать гибкое, документоориентированное хранилище для артефактов системного аналитика (ТЗ, API-контракты, диаграммы, Use Case), позволяющее хранить разнородные данные без жесткой нормализации и сложных миграций схемы.

## 2. Обоснование выбора MongoDB
- **Гибкость схемы:** Разные типы артефактов (например, текстовое ТЗ и метаданные PNG-диаграммы) имеют разные наборы полей. MongoDB позволяет хранить их в одной коллекции без `NULL`-полей.
- **Производительность чтения:** Быстрый доступ к целому документу по `_id` или индексу без необходимости `JOIN` (как в реляционных БД).
- **Масштабируемость:** Удобное добавление новых метаданных (например, `review_status` или `approver`) без изменения структуры всей коллекции.

## 3. Структура документа (Коллекция `artifacts`)
Документ представляет собой единый JSON-объект, содержащий все метаданные и содержимое артефакта.

| Поле | Тип данных | Обязательное | Описание |
| :--- | :--- | :---: | :--- |
| `_id` | ObjectId | Да | Уникальный идентификатор документа (генерируется автоматически). |
| `title` | String | Да | Название артефакта (напр., "ТЗ: Бэкенд сайта"). |
| `type` | String (Enum) | Да | Тип артефакта: `requirements`, `diagram`, `contract`, `use_case`. |
| `category` | String | Да | Категория: `backend`, `frontend`, `architecture`, `analytics`. |
| `description` | String | Да | Краткое описание назначения артефакта. |
| `file_name` | String | Да | Имя оригинального файла (напр., `api-spec.yaml`). |
| `file_type` | String | Да | Расширение файла: `md`, `yaml`, `png`, `pdf`. |
| `file_path` | String | Да | Путь к файлу в репозитории или URL для скачивания. |
| `tags` | Array[String] | Нет | Список тегов для гибкой фильтрации (напр., `["fastapi", "docker"]`). |
| `version` | String | Нет | Версия документа (напр., "1.0.0"). |
| `author` | String | Да | Автор артефакта (напр., "Лобашев Андрей"). |
| `created_at` | Date | Да | Дата и время создания (ISODate). |
| `updated_at` | Date | Да | Дата и время последнего обновления (ISODate). |

## 4. Требования к индексации
Для обеспечения быстрого поиска и фильтрации (время отклика < 50 мс) необходимо создать следующие индексы:
1. `type_1_category_1` (составной индекс) – для фильтрации по типу и категории.
2. `tags_1` (мультиключевой индекс) – для поиска по тегам.
3. `created_at_-1` – для сортировки списка артефактов по дате создания (от новых к старым).
